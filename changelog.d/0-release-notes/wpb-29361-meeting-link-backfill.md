This change ships an application-level data migration (no schema migration): a background pass in galley backfills a live join code for every meeting that does not have one, so every meeting exposes a canonical join `link` on the V19 API shape. Existing join codes and links are never rotated by the backfill.

Operators must run with `postgresMigration.conversationCodes: postgresql` (or `migration-to-postgresql`) and have a join-link URI configured (`settings.conversationCodeURI`, or the user's domain in the `multiIngress` map); otherwise meetings without a live join code (pre-link-feature rows) return `500 link-unavailable` on reads across all API versions (legacy V15–V18 shapes included; their response *shapes* are unchanged) until the first backfill pass completes, and meeting creation fails with `500 link-unavailable` in misconfigured deployments.
